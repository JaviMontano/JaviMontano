Flujo de productividad.

Los procedimientos no nacen como teoria; salen de tareas con fecha, evidencia y cierre.

flowchart LR
  A["work/ con fecha"] --> B{"Sesion iniciada?"}
  B -- "No" --> C["WIP"]
  B -- "Si" --> D["Tarea en procedimiento"]
  D --> E{"Cierre / resultado?"}
  E -- "No" --> C
  E -- "Si" --> F["Cerrada"]
  F --> G["Procedimiento reutilizable"]
  G --> H["Dashboard / evidencia publica sanitizada"]

UX/UI del sistema.

Este dashboard se disena para lectura repetida: denso, escaneable, sin hero decorativo excesivo, con controles esperables y datos cerca de las decisiones.

Principios de interfaz

  • Densidad utilMuchas senales, poco adorno. Cada bloque debe ayudar a decidir.
  • Navegacion estableTabs por vista, sidebar persistente, tabla para auditoria y kanban para operacion.
  • ExtensibleLas tareas y procedimientos salen de datos; agregar nuevos slugs no exige redisenar la pagina.
  • PrivacidadLos datos privados quedan como origen local; la pagina muestra metadatos publicables.

Decision model

Si hay fecha, hay tarea. Si hay estructura, hay procedimiento candidato. Si hay cierre y evidencia, puede convertirse en procedimiento reusable. Si no hay sesion/cierre, queda WIP.
